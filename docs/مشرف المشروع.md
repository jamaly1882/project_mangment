# مشرف المشروع (مشرف البند) — الدخول وتسجيل الكميات والتكاليف

## 1. الدخول

1. يفتح المشرف التطبيق ويُدخل **اسم المستخدم وكلمة السر** اللذين أنشأهما له
   مدير إدارة المشاريع (أو مسؤول النظام من صفحة المستخدمين).
2. يُوجَّه تلقائيًا إلى **لوحة مشرف البند** التي تعرض البنود المسندة إليه فقط.
3. إذا لم تظهر بنود، فالسبب غالبًا أن البند لم يُسند إليه من صفحة
   «تفاصيل البند» لدى مدير المشروع (تُكتب الإسنادة في `item_supervisors`).

### الأدوار المقبولة

| الدور في `users/{uid}.role` | النتيجة |
| --- | --- |
| `project_supervisor` (الهيكل الجديد) | حساب مشرف — يعمل |
| `supervisor` (قديم) | حساب مشرف — يعمل |
| `driver` (قديم جدًا) | يُعامَل كمشرف ميداني بعد التطبيع |
| أي دور آخر | رسالة توضح أن الحساب ليس حساب مشرف مشروع |

كانت صفحة البند تقبل حرفيًا الدور `supervisor` فقط، فكان مشرف المشروع
الجديد (`project_supervisor`) يرى رسالة «هذا الحساب ليس مشرف بند فعلًا».
أُصلح ذلك عبر `AppRoles.isFieldSupervisor` التي تُطبّع الدور قبل المقارنة.

### ربط المشروع

تُقرأ مشاريع المشرف من `projectIds` (قائمة) أو `projectId` (حقل مفرد)
أو من الإسنادات نفسها. لا يمنع التطبيق الدخول عند غياب الربط، بل يعرض
البنود المسندة إلى الحساب مباشرة.

## 2. صفحة البند وتفاصيله

يفتح المشرف البند من لوحة المشرف (زر «عرض البند وتسجيل الكميات»)، فتظهر:

- بيانات البند: الاسم والنوع والكود والمشروع والكمية التعاقدية والمنفذة والمتبقي.
- المعدة المسندة وقراءة عدّادها وقت الإسناد (للعلم فقط).
- **تسجيل الكمية المنفذة**: يُدخل الكمية المنجزة فعلًا وتُضاف إلى الكمية
  المنفذة السابقة داخل معاملة (Transaction) بلا تجاوز للكمية التعاقدية،
  وتُحدَّث معها `executedCost` وتكاليف المشروع `ProjectCostSync`،
  ويُسجَّل سطر في `item_executions` للمتابعة.
- **التكاليف الفعلية**: أربعة أقسام بأسطر (المواد، العمالة، المعدات،
  المحروقات)، مع مقارنة سطرًا بسطر بالمخطط الذي أدخله مدير المشروع.
  ساعات العمل والوقود والزيت تُسجَّل كأسطر داخل قسمي المعدات والمحروقات،
  ولا توجد حقول استهلاك مستقلة (أُزيلت بطاقة «الاستهلاك الفعلي» لأنها
  كانت ازدواجًا مع أسطر التكلفة).
- مجاميع المشروع بعد الحفظ، وتُحسب من البنود ولا تُدخل يدويًا.

### حقول قديمة لم تعد تُستخدم

الحقول `executedWorkingHours` و`consumedFuelQuantity` و`consumedOilQuantity`
لم تعد تُدخل من التطبيق ولم تُعد تُعرض في لوحة المشرف. تبقى البيانات
المحفوظة سابقًا في Firestore كما هي دون حذف، وتُقرأ في تقرير المحروقات
عند وجودها، لكن مصدر الاستهلاك المعتمد الآن هو أسطر التكلفة.

## 3. ما لا يفعله المشرف

- لا يغيّر بيانات التكليف (المشرف أو المعدة) ولا الكمية التعاقدية.
- لا يعدّل قراءة عدّاد المعدة؛ فهي من صلاحية إدارة الحركة.
- لا يدخل تكاليف المشروع الإجمالية مباشرة.

## 4. أين تُحفظ البيانات

| البيانات | المجموعة / الحقول |
| --- | --- |
| الإسناد | `item_supervisors/{itemId}` بحقل `supervisorId` و`active` |
| الكمية المنفذة | `items/{itemId}.executedQuantity` + نسخة في `item_details` |
| تكلفة التنفيذ | `items/{itemId}.executedCost` |
| حركة التنفيذ | `item_executions` (سطر لكل إضافة كمية، `source = supervisor`) |
| التكاليف الفعلية | أسطر `*ActualLines` ومجاميعها في `item_details` و`items` (تشمل ساعات العمل والوقود والزيت) |
| تكاليف المشروع | `projects/{projectId}` (تُكتب آليًا من `ProjectCostSync`) |
