===================================================
تحديث: التكاليف + مشرف البند (بدل السائق)
===================================================

مدير النظام (Admin)
│
├── إضافة محافظة           → governorates
├── إضافة مديرية           → districts
├── إضافة بند              → item_definitions
├── إضافة نوع              → item_definitions/{bnd}/types
├── إضافة مشروع            → projects
│     ├── اسم المشروع + الكود
│     ├── المحافظة + المديرية
│     └── تاريخ البداية + المدة
│     (لا يخير المستخدم بأي حقل تكلفة)
│     والتكاليف التي تظهر في المشروع = مجموع بنوده:
│           ├── materialsCost   تكلفة المواد
│           ├── laborCost       تكلفة أجور العمالة
│           ├── equipmentCost   تكلفة المعدات
│           ├── fuelCost        تكلفة المحروقات
│           └── totalCost       الإجمالي
│     وتُكتب آليًا بواسطة ProjectCostSync.applyTotals
├── إضافة مدير للمشروع     → users + projects.managerId
└── إضافة مستخدمين          → users
      ├── مهندس   (engineer)
      └── مشرف بند (supervisor)  ← حلّ محل تبويب السائقين

مدير المشروع (Project Manager) — يدخل باسم المستخدم وكلمة المرور
│
├── لوحة مدير المشروع
│     └── بطاقة «تكاليف المشروع — محسوبة من بنوده» (ProjectCostSync)
│
├── صفحة البنود → إضافة بند
│     ├── 1) تحديد البند (item_definition)
│     ├── 2) تحديد النوع (type)
│     ├── 3) الكود + الكمية التعاقدية + الوحدة
│     ├── 4) المهندس + المعدة + مدة العقد
│     └── حفظ → صفحة تفاصيل البند
│
└── صفحة تفاصيل البند = صفحة التكاليف نفسها (item_details/{itemId})
      ├── 1) بيانات البند
      │     ├── البند + النوع + كود البند (للقراءة)
      │     ├── الكمية التعاقدية * + الوحدة *  (قابلة للتعديل هنا)
      │     └── تفاصيل البند + ملاحظات
      ├── 2) تكاليف البند (المخطط) = جدول أسطر لكل قسم
      │     ├── المواد    : نوع المادة · الوحدة · سعر الوحدة · الكمية · التكلفة
      │     ├── العمالة   : المهنة · العدد · أساس الأجرة · الأجرة · المدة · التكلفة
      │     ├── المعدات    : نوع المعدة · العدد · الوحدة · سعر الوحدة · الكمية · التكلفة
      │     ├── المحروقات : نوع الوقود · الكمية · الوحدة · سعر اللتر · التكلفة
      │     ├── التكلفة = ناتج معادلة القسم تلقائيًا أو تُثبَّت يدويًا (manual)
      │     ├── المجاميع → materialsCost / laborCost / equipmentCost / fuelCost
      │     │              + totalCost + مرايا *UnitCost = القسم ÷ الكمية التعاقدية
      │     └── الأسطر في  materialLines / laborLines / equipmentLines / fuelLines
      │     ├── إجمالي تكاليف البند = المجموع (totalCost)
      │     └── بطاقة «تكلفة البند مقابل مشروع بعد الحفظ»
      │           (نصيب البند من كل قسم + مجموع بنود المشروع الأخرى)
      ├── 3) التنفيذ (للقراءة)
      │     نسبة التنفيذ + الكمية المنفذة + المتبقية + بداية ونهاية التنفيذ
      ├── 4) المسؤول عن البند
      │     ├── مشرف البند (بدل السائق) → supervisorId / supervisorName
      │     │     (يُختار من مستخدمين مسجلين في النظام — لا إنشاء من هنا)
      │     └── المعدة  → equipmentId
      │
      │     (أُلغيت من هذه الصفحة حقول: نوع الوقود، كمية الوقود المخططة،
      │      كمية الزيت المخططة، ساعات العمل المخططة — الاستهلاك المخطط
      │      يُدخل الآن أسطرًا في «تكلفة استهلاك المحروقات» ضمن تكاليف البند،
      │      ويتوقف الحفظ عن كتابة fuelType/defaultFuelQuantity/
      │      defaultDieselQuantity/defaultOilQuantity/defaultWorkingHours،
      │      أما القيم القديمة المحفوظة في البنود الحالية فتبقى كما هي
      │      وتظهر لمشرف البند في بطاقة «حدود الاستهلاك».)
      └── الحفظ يكتب في: item_details + items + item_supervisors/{itemId}
          ثم ProjectCostSync.applyTotals(projectId)

مشرف البند (Supervisor)
│
├── تسجيل الدخول باسم المستخدم → SupervisorPage
│     (بطاقة البند تعرض: التعاقدية + المنفذة + المتبقي + نسبة التنفيذ)
├── البنود المسندة إليه من item_supervisors (+ fallback لسجلات item_drivers القديمة)
└── صفحة البند عنده = AssignmentDetailsPage (مشرف البند فقط)
      ├── 1) الاستهلاك الفعلي → item_details
      │     consumedFuelQuantity / consumedOilQuantity / executedWorkingHours
      │     + علامات تجاوز المخطط (fuelExceededPlanned / ...)
      │     تُقرأ الحدود من default* القديمة؛ للبنود الجديدة لا حدود
      │     فتعرض «غير محدد» ولا يُعلَّم تجاوز (بدون أي رفض للحفظ).
      ├── 2) التكاليف الفعلية للبند = نفس جداول الأسطر الأربعة (حقول Actual)
      │     materialsActualCost / laborActualCost /
      │     equipmentActualCost / fuelActualCost  (+ *ActualUnitCost)
      │     الإجمالي = تكلفة الوحدة × الكمية (المنفذة وإلا التعاقدية)
      │     أو يدخله المشرف يدويًا
      │     actualTotalCost = مجموع الأقسام
      └── بعد الحفظ: ProjectCostSync.applyTotals(projectId)

      حسابات أدوار التكلفة:
      • مخطط (planned)  = إدخال مدير المشروع  → materialsCost ... totalCost
      • فعلي (actual)   = إدخال مشرف البند     → materialsActualCost ... actualTotalCost
      • معتمد (effective) = الفعلي للقسم إن وُجد وإلا المخطط → effectiveTotalCost
      صفحة المشروع ولوحة مدير_project يعرضون المخطط مقابل الفعلي،
      والإجمالي المعروض هو المعتمد.

تحديث: تكاليف المشروع مجمّعة من البنود
===================================================

• lib/core/services/project_cost_sync.dart
  ProjectCostSync.totalsFor(projectId)  → حساب فقط (للعرض)
  ProjectCostSync.applyTotals(projectId)→ حساب + حفظ في وثيقة المشروع
  يقرأ: items where projectId == المشروع
  ويكتب في projects/{id}: materialsCost / laborCost / equipmentCost /
  fuelCost / totalCost + costsSource = auto_from_items +
  costsItemCount (بنود لها تكلفة) + costsProjectItemCount (كل البنود) +
  costsUpdatedAt.

• مواضع الاستدعاء:
  1) بعد إضافة مشروع (admin/projects_page)
  2) بعد حفظ تفاصيل البند (item_details_page)
  3) بعد إضافة بند جديد (add_item_page)
  4) بعد تسجيل كمية منفذة (items_page)
  5) زر «إعادة حساب التكاليف» في بطاقة المشروع

• صفحة إدارة المشاريع: لا حقول تكلفة — بطاقة توضح أن التكاليف تأتي من
  البنود، وقسم «تكاليف المشروع (محسوبة من البنود)» مع ملاحظة عدد البنود
  وآخر تحديث.

ملاحظات تقنية
• الحقول: materials / labor / equipment / fuel في المشروع = إجماليات محسوبة،
  ولا تُدخل يدويًا أبدًا.
• في البند: أسطر مفصّلة لكل قسم، ومجاميعها تُكتب في نفس الحقول القديمة،
  ويُحسب executedCost = مجموع تكلفة الوحدة × الكمية المنفذة عند إضافة كمية.
• دور السائق مغلق في التطبيق: صفحة DriverPage تعرض رسالة فقط تطلب من
  مسؤول النظام تحويل الحساب إلى «مشرف بند» من صفحة المستخدمين، وبعدها
  تظهر لنفس المستخدم البنود المسندة قديمًا عبر item_drivers.
• item_supervisors يسجّل للمشرفين، والسجلات القديمة تُعطَّل (active=false)
  عند حفظ الإسناد الجديد.
• AssignmentWorkspacePage يبقي مفتاح supervisorMode لقراءة اللوحات القديمة
  فقط، أما صفحة التفاصيل فمشرف البند حصرًا.

===================================================
تحديث: تكاليف البند بأسطر مفصّلة (سطر لكل مادة/مهنة/معدة/وقود)
===================================================

المحرر:
• lib/core/utils/cost_lines.dart          النموذج + المعادلات + الترحيل
• lib/core/widgets/cost_lines_editor.dart بطاقة الأسطر + CostLinesEditorController

معادلات الأقسام:
• المواد    : التكلفة = سعر الوحدة × الكمية
• العمالة   : التكلفة = العدد × الأجرة × المدة
              (أساس الأجرة: يومي / ساعي / للوحدة — يغيّر معنى الأجرة والمدة فقط)
• المعدات    : التكلفة = العدد × سعر الوحدة × الكمية
• المحروقات : التكلفة = الكمية × سعر اللتر

القواعد:
• كل الأسعار تُدخل داخل السطر؛ لا حقول أسعار في صفحة المواد أو حصر المعدات.
• زر «تثبيت يدوي» لكل سطر يضبط manual=true فتبقى تكلفته كما كُتبت،
  و«إلغاء» يعيدها إلى الحساب التلقائي.
• البند الذي له رقم مفرد قديم بلا أسطر يظهر كسطر بشارة «إدخال قديم»،
  وأول حفظ يحوّله إلى سطر حقيقي (لا تُحذف بيانات).
• اختيار المادة أو المعدة من بيانات النظام يعبّئ الاسم فقط
  (materialId / equipmentId) والحساب لا يعتمد على بيانات النظام.
• الحفظ (عند المدير = مخطط، وعند المشرف = فعلي) يكتب في item_details و items:
  الأسطر + مجاميع الأقسام + totalCost أو actualTotalCost + مرايا *UnitCost
  + costsModel = lines + costsLineCount،
  ثم ProjectCostSync.applyTotals(projectId) يحدّث وثيقة المشروع
  (مخطط / فعلي / معتمد) كما هو بدون أي تعديل على الاستعلامات.
• مدير المشروع يحدد المخطط، ومشرف البند يحدد المستهلك الفعلي.
• بطاقة «مقارنة الأسطر» (CostLinesComparison) تعرض لكل قسم: البيان ·
  المخطط · الفعلي · الفرق، وشارات: تجاوز / أقل من المخطط /
  غير مخطط / لم يُستهلك، مع سطر ملخّص لكل قسم ثم سطر الإجمالي.
  تظهر تلقائيًا إذا وُجد سطر عند أي من الطرفين (CostLines.diff).
• الفرق على مستوى السطر تقريبي: السطر i يقابل السطر i في نفس القسم،
  والاعتبار الأول لمجموع القسم.
• عدد الأسطر محفوظ في costsLineCount (مخطط) وactualCostsLineCount (فعلي)
  على وثيقة البند، ويُجمَّع في وثيقة المشروع بنفس المفتاحين،
  وتعرضه بطاقة «تكاليف المشروع (محسوبة من البنود)».

===================================================
النشر وقواعد Firestore
===================================================

الملفات المضافة إلى المستودع:
• firestore.rules          الطبقة المفعّلة: القراءة والكتابة لمستخدم
                           مسجّل الدخول فقط (إغلاق وضع Test mode)،
                           ونسخة قواعد الأدوار معلّقة بالأسفل جاهزة.
• firestore.indexes.json   قائمة الفهارس — فارغة على قصد: كل استعلامات
                           التطبيق إما مستندية أو equality على حقل واحد،
                           فلا حاجة لفهارس مركّبة.
• firebase.json            أُضيف قسم "firestore" الذي يشير إلى الملفين.

التحقق والنشر من جذع المستودع:
  firebase deploy --only firestore:rules,firestore:indexes
  firebase deploy --only hosting        # بعد flutter build web --release

ملاحظات مهمة:
• صفحة الدخول تقرأ users/{uid} بعد نجاح signIn، وإنشاء الحسابات من صفحات
  المسؤول؛ لذلك لا يوجد أي وصول مطلوب قبل تسجيل الدخول، وقاعدة
  «المسجّل فقط» لا تكسر أي شاشة.
• تكاليف المشروع تُكتب من كود التطبيق (ProjectCostSync) في وثيقة المشروع،
  فأي تقييد لاحق يجب أن يسمح لـ project_manager و supervisor بكتابة حقول
  المجاميع (القائمة في تعليق costFields() داخل firestore.rules).
• قواعد Firestore تُجمَّع بالـ OR: إبقاء القاعدة العامة match /{document=**}
  يجعل أي قاعدة أدوار مضافة لاحقًا بلا أثر، فلا بد من حذفها عند التفعيل.
• القواعد لا تمنع القراءة من كود التطبيق (لا يوجد SDK خفي يحمي البيانات):
  شدّدها خطوة خطوة وجرّب كل شاشة بعد كل تغيير.
• إن أردت تثبيت مشروع الـCLI بدون تمرير --project كل مرة:
  أنشئ .firebaserc واكتب فيه {"projects":{"default":"project-manager-9280b"}}.

نمط القوائم المنسدلة في النوافذ (Flutter الحديث)
=================================================

• DropdownButtonFormField صار يستخدم initialValue بدل value (المهمل منذ
  v3.33). الفرق سلوكي لا شكلي: value كانت تجعل القائمة تتبع setState،
  أما initialValue فتهيّئ الحقل مرة واحدة فقط.

• إن كانت قيمة القائمة تتغير من غير يد المستخدم (زرّ مسح، إعادة تعيين
  النموذج، تحميل بيانات بعد الفتح) أعطِ الحقل مفتاحًا يتغيّر مع القيمة:
      key: ValueKey<String?>('equipment-driver-$selectedDriverId')
  فتُعاد تهيئة حالة FormField وتُقرأ initialValue من جديد، ولا يبقى
  الاختيار المحذوف ظاهرًا. مطبَّق في admin/equipment_page.dart
  (اختيار مشرف المعدة)، وبقيت حالتا «حالة المعدة» و«حالة التسجيل»
  بلا مفتاح لأن قيمتهما تتغيرا من المستخدم فقط.
